One custom block response for every WAF block

NET-024 · AWS WAF + Firewall Manager + CloudFront. Managed rule group blocks have no custom response, so they return the default 403. WAF has no setting for all rules; CloudFront can serve one 403 page for all of them.

1. The symptom

~30% · responseCodeSent
~70% · no responseCodeSent

Own rules (rate-based, custom groups) have a custom response. AWS managed rule group rules don't, so their blocks fall back to the default response.

2. Which response a blocked request gets

1. WAF Block action custom response — if present, it is used and nothing else applies.
2. Protected resource custom response — CloudFront custom error response by status code (403).
3. WAF default Block response — 403 Forbidden.

3. The four questions

QuestionAnswer
One setting for all rules?Not in WAF Custom responses are set per Block action. CloudFront a 403 custom error response covers every block without a WAF custom response.
Block + CustomResponse in ruleActionOverrides?WAF API valid (ActionToUse is a full RuleAction). Firewall Manager not supported — PutPolicy succeeds but silently stores {"block": {}} (lab, 2026-11-04). Central fix: a rule group in the FMS administrator account with its own CustomResponseBodies.
Count + label block?Valid. Prefer group-level OverrideAction: Count — it covers rules AWS adds later. Rule-level overrides need every name and invalid names are silently ignored.
Where in a retrofitted web ACL?Last preProcess group. Try the simulator below.

6. Common mistakes

  • Looking for a global WAF switch — the global switch is the CloudFront 403 page.
  • Label block in postProcess — own Allow rules skip it.
  • Blocking a too-broad namespace — some managed rules are Count by default; check Rules[].Action.
  • Forgetting that the CloudFront 403 page also replaces origin 403s.
